# Save states across process restarts

The own-engine save manager now reads `psxlab/states/*.psxlabstate` instead of the retired backend's state directory. Slot discovery and PNG previews work without a running VM. A saved original source lets the library resolve the game and cold-launch its slot after process death.

Starting in 0.3.32, slot filenames are keyed by the disc's boot game ID plus a SHA-256 fingerprint of its boot executable. The fingerprint separates different boot revisions/translations that reuse a serial. Executables without a disc serial use their content fingerprint. Renaming the image, changing between equivalent containers, moving it, or launching it through another URI does not change this key. It is derived from the mounted media in the backend, so library and external-frontend launches use the same rule.

The version-3 outer header stores this stable identity separately from the original game and mounted-disc sources. The compressed machine payload retains its original identity for checksum/schema validation. An empty disc source means the freshly prepared boot image. Swapped discs retain their original URI and are prepared again before restoring. Prepared copies close after their CD readers and are released when no longer needed.

Version-1 and version-2 states remain readable. Before emulation starts, legacy source identities are matched using the original/library/first-disc addresses or by opening the old media and deriving its ID. Successful lookups are cached in small `states/source-*.id` files; unrelated images are not reopened in the playback loop. A missing old image is left untouched rather than matched by filename. Staged identities require the complete original document-URI digest.

For matching legacy slots, migration keeps the newest timestamp if multiple launch paths used the same slot, and never overwrites an existing canonical slot. Original states and previews, including conflicting older versions, are retained under `states/legacy/<migration-id>/`. Archiving originals outside slot discovery prevents a deleted migrated slot from reappearing on the next boot. Inaccessible or unidentified states remain available for later recovery. Full machine validation still checks identity, architecture, BIOS checksum and device schema. Existing SwanStation-format states remain incompatible and are not converted or deleted.

PSX Lab's codec excludes memory-card contents, so checked loads retain current card data. Export backups include own-engine states, the legacy archive, cards, the autosave source index and the stable autosave-key index. The key index is accepted only when its recorded source matches the autosave source, so a partial index update can fall back to metadata discovery.

Host regressions cover all numbered slots/autosave, reopening the store, version-1 recovery, unrelated-game isolation, truncated headers, original-file preservation, library recovery from a URI digest and retaining current card contents on restore.

`StatePersistenceIntegrationTest` additionally runs `writeState` and `reopenState` in separate Android instrumentation processes, with the same unique `auditId`. It uses a private `performance/state-persistence-<auditId>` root and the existing synthetic `fixtures/game.chd`, with a fresh launch path in each process. The current fixture changes from a library content URI to a renamed frontend file URI, and checks RAM restoration from numbered/autosave slots. Player saves/cards/settings are never used as test destinations.
